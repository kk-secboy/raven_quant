# 模型数据准备复用

## 目标与范围

模型竞赛的主要重复工作是从 Qlib bin 计算特征，再按训练窗口拟合归一化器。
bin 保存行情字段，不能直接代替这些已经处理好的训练数据。

执行器 `model-recompute-docker-v12-progress-observed` 将这一步交给固定的独立准备程序。
同一数据身份、股票池、特征与标签定义、训练窗口、预测结束时间和访问权限下，
不同模型与种子复用一份处理结果。每个模型仍独立训练、预测、回测和产出检查点。
特征、训练日期、数据精度、种子、成本、策略规则与样本外门槛不变。

不同训练窗口分别拟合 RobustZScoreNorm，完整横截面计算标签标准化。
研究、正式样本外、实时推理与重新训练不能共用不同访问范围的制品。
请求同时绑定原始数据身份、实际交易日历、市场成员清单、附加因子内容与
准备程序及固定镜像的身份。候选模型代码、任务 ID 和随机种子不进入数据缓存键。

## 执行与审计

1. 可信控制器先校验数据请求，再查找完整制品；相同请求最多同时构建一份。
2. 缓存缺失时，固定 Docker 准备程序只读取数据和受控源码，接触不到候选模型代码。
3. 数值数组以保留 dtype 的 `.npy` 文件保存，索引与清单使用 JSON/数值数组。
   不使用 pickle 或对象数组；完整内容校验后原子发布。
4. 模型仅获得自己的数据目录及租约文件的只读挂载，通过 memory map 恢复。
   模型使用原有 Qlib 数据访问实现，按需生成训练或预测矩阵。
5. 每次执行保留请求、制品清单副本、命中情况与结果绑定。缓存删除不会删除历史审计。

等待租约、准备数据及模型训练使用 `observe_only` 进度观察，不因固定总耗时自动终止。
兼容入口的旧超时数值只保留请求审计；运行 30 分钟或连续 30 分钟未观察到计算进展时
提示检查，不能仅因缺少可见进展认定进程卡死。用户取消、内存硬限额和真实异常仍停止。
资源上限没有因缓存而增加。
缓存内容损坏会明确失败；存储容量不足才回到同一套未缓存的数据计算路径，并标记
`uncached_capacity`。数据制品身份属于每次执行的证据，不混入跨模型比较时必须一致的
`execution_environment`。

## 空间与并发

Worker 将共享目录设置为 `DATA_ROOT/artifacts/model-prepared-data`，通过
`MODEL_PREPARED_DATA_ROOT` 传给模型执行器；WSL 使用对应的 Linux 路径。
直接调用执行器时也可设置该环境变量，但目录必须能从私有 Docker daemon 以相同路径挂载。
共享目录不能经过符号链接或 Windows reparse point。

默认缓存预算为 128 GiB，要求所在文件系统至少保留 32 GiB 空闲空间。
LRU 只回收未使用的完整缓存项；控制器和模型进程各自持有只读使用租约，
控制器退出后仍运行的模型继续受到保护。锁文件的 inode 是租约身份，不能单独删除。
失败构建会清理本次 staging。硬终止后，仅在构建锁和准备程序的租约都空闲时，
才回收可识别的遗留 staging；无法确认归属或仍被使用的目录继续计入预算。

共享预处理不代表可以直接提高模型并发。应根据训练峰值重新评估主机余量，
原有 40 GiB 模型预算与全局资源账本继续生效。

## 验证与发布

常规回归覆盖 request、store、cache、handler、producer 和 execution 模块。
Linux 验收使用与生产相同 digest 的 Qlib 镜像，运行真实文件锁、原子发布与 Qlib 数据访问；
Windows 的条件跳过不能替代这些验收。

`scripts/benchmark_model_prepared_data.py` 用已有的受控 manifest 和只读 provider 做全量对比。
`prepare`、`verify`、`warm` 分别在新进程中执行，使用同样的 CPU/内存限制：

```text
python -I scripts/benchmark_model_prepared_data.py --manifest MANIFEST --provider PROVIDER --output OUTPUT --mode prepare
python -I scripts/benchmark_model_prepared_data.py --manifest MANIFEST --provider PROVIDER --output OUTPUT --mode verify
python -I scripts/benchmark_model_prepared_data.py --manifest MANIFEST --provider PROVIDER --output OUTPUT --mode warm
```

输出目录必须是独立工作区，且容器内的绝对路径不能包含名为 `artifacts` 的目录，
以满足现有 MLflow FileStore 路径要求。`prepare` 要求目标目录不存在。
报告记录全量数值、dtype、索引和分段数据访问的精确对比，以及准备、写入、校验、
首次访问耗时和内存峰值。系统页缓存不清空，因此 `warm` 只表示复用预处理制品；
数据基准不等于完整模型训练和生产活动已经通过。

升级必须使用新的、完整封存的运行时身份。正在运行的竞赛与活动继续使用原有发布版本；
不能在其种子或候选模型之间切换源码、混用执行器身份，或重置重试计数来强行接入。
数据基准和隔离回归通过后，在新的完整活动边界发布，并重新验证正式执行证据。

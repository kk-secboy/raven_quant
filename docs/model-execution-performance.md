# 统一研究提速

本版本把数据准备复用、实验单元调度、训练线程、断点续跑与研究周期拆分统一发布。
产品语义以[根设计稿](../个人量化投资与模拟盘系统设计稿.md)为准。

## 执行合同

- 数值预处理见[模型数据准备复用](model-prepared-data.md)。同请求最多准备一份，模型仅只读使用。
- 单元按模型、窗口和种子独立执行，整个批次仍占原有全局资源账本预算；内部最多两个单元，
  合计不超过 8 CPU / 40 GiB。固定资源档位必须覆盖准备和训练峰值，不能仅按当前 RSS 放行。
- 原生计算线程、LightGBM 线程、Torch 计算线程与 DataLoader 进程分别配置；
  增加计算线程不等于增加数据加载进程。整张固定策略进入实验环境身份。
- 成功单元完成全部输出校验后原子提交回执。同任务、输入和运行版本的后续 attempt
  可以恢复已提交单元。已失败单元保留失败，不给予新的统计机会，旧结果不会被覆盖。
- 不同种子仍各自训练，不缩短训练区间，不改变特征、标签、训练轮数或准入条件。
- 模型计算不因固定总耗时自动终止。`observe_only` 记录运行阶段、累计时间与可见进展，
  运行超过 30 分钟触发长时间提示；连续 30 分钟未观察到计算进展也只提示检查，不直接判死。
  用户取消、内存硬限额、执行异常和完整性检查继续生效；网络 RPC 超时、因子代码隔离
  限额与 RD-Agent 主动研究时长预算保持各自范围。旧 timeout 请求字段仅作审计。
- 重复资源预检并入首个正式实验格，其成功训练、预测、回测与资源审计直接计入原有九格，
  不再额外重复训练。失败保留失败，不能更换数据或资源反复试到通过。

## 持续研究与模型重选

| 周期类型 | 短线 | 中线 | 长线 |
| --- | --- | --- | --- |
| 持续研究 | 每周 | 每月 | 每季度 |
| 完整模型重选 | 每月 | 每季度 | 每年 |

已有兼容冠军且重选未到期时，复用冠军配方与组件，按当前数据完成完整三窗口、三种子
重验后继续 RD-Agent 多轮研究。无兼容冠军、显式完整活动和契约迁移仍需完整选拔。
选拔模式及其来源在活动中冻结，不能在失败后切换模式或把旧评分当作当前证据。

## 验证与发布

必须验证进程并发与硬预算、失败/取消资源释放、成功回执篡改检测、跨 attempt 恢复、
原生 Qlib 结果及新旧周期衔接。性能探针与生产活动隔离，缩小的诊断样本不能当作
全量实验或正式样本外证据，线程测试不能直接换算为完整主线提速倍数。

统一发布使用完整封存的 v43 源码和迁移 `0115_strategy_runtime_v43`。旧活动的结果与
消费记录保留，不能在同一场竞赛中混用 v42 和 v43。发布后需核对所有服务源码、数据库版本、执行器、线程策略以及
新活动的缓存命中、单元回执和资源审计，再确认提速机制在生产生效。

## 2026-09-07 隔离测量

固定生产 Qlib 镜像下，完整 Alpha158 数据包含 9,639,197 行、158 个特征。
一次准备耗时 1,246.877 秒；两个独立执行边界均重新校验全部文件 SHA 后，
恢复分别耗时 14.576 和 19.468 秒。该测量仅覆盖数据准备与恢复，不包含模型训练和回测。

另用相同的 580,597 行训练、150,232 行验证切片比较线程，LightGBM 训练加预测
在 2 / 4 / 8 线程下分别耗时 9.539 / 5.132 / 2.967 秒，预测字节一致。
这是使用提前停止的小型诊断，不能直接推断全量训练耗时；据此将 LightGBM 固定为
8 线程，其余默认 4 线程，数据准备固定 1 个原生线程和 1 个 Qlib kernel。
Ridge 跨线程的浮点预测不承诺逐位相等，因此线程策略整体属于新执行环境身份。

原生 Qlib DatasetH 和 TSDatasetH 各用三个种子比较 DataLoader 的 0 与 2 个进程，
保持计算线程相同；三轮训练的批次、损失、模型张量和预测全部逐位相等。
生产固定 DataLoader 为 0，避免各单元额外复制数据、占用 CPU 和内存。
